# Assumptions — PortPulse

For judges who ask follow-up questions about the data and scope.

## Data

- **All vessel and port data is synthetic.** It is generated by `src/simulation/generator.py` using a seeded random number generator to ensure reproducibility.
- The vessel arrival distribution (class mix, cargo volumes, inter-arrival times) is modelled on publicly documented container port statistics but is not sourced from any live feed.
- Port capacity (8 berths, 20 cranes, throughput rates) is representative of a mid-size container terminal; no specific real port is being modelled.

## Scope Cuts

- **Single port only** — multi-port network effects are out of scope.
- **No real-time AIS integration** — vessel ETAs are simulated.
- **No user authentication** — the prototype is a single-user local demo.
- **No persistent storage** — API state resets on server restart.
- **Prediction model is rule-based, not ML** — deliberate choice to keep it explainable and demo-ready (see `docs/decisions.md`).
- **Optimizer is greedy, not globally optimal** — OR-Tools CP-SAT noted as v2 upgrade path.

## What the Demo Shows

The demo scenario injects:
1. A burst of 8+ extra vessel arrivals concentrated around hour 24 of the 72h window.
2. Berth B05 (South Terminal A) taken offline (maintenance).

This combination reliably triggers HIGH/CRITICAL congestion risk scores on berths B03–B06, showing the prediction module working. The optimizer then reroutes affected vessels, visibly reducing average wait time.
